# Sprint 01 — Runtime, CLI, Auth Base

**Milestone:** M1
**Effort:** 3-5 days
**Dependencies:** none — start here

## Goal

Bootstrap the app: install command, systemd user service, HTTP server on
`127.0.0.1:4096`, password setup, secure session cookies, and the CLI surface
that every later sprint depends on.

## In-Scope Requirements

- REQ-001 through REQ-014D (install, runtime, CLI, auth, password hashing,
  sessions, rate-limit, CSRF)
- REQ-090A (atomic JSON writes + current-user permissions baseline)
- REQ-108 through REQ-110 (route grouping, normalized command envelopes,
  normalized errors — baseline helper only)
- NFR-001 (auth on every endpoint except login)
- NFR-006 (0.0.0.0 warnings)
- NFR-008A (HTTPS vs password clarity)

## Out of Scope

- Project picker, provider selector (sprint 02)
- Any provider adapter (sprint 03+)
- File or terminal APIs (sprint 06)

## Pre-flight Decisions (locked)

These are decided up-front so the sprint plan does not have to brainstorm
mid-implementation. Full rationale lives in
[architecture.md §22](../architecture.md#22-sprint-01-pre-flight-decisions).

| # | Decision | Tasks touched |
|---|---|---|
| P1 | First-run password set via CLI prompt inside `install` (confirm-twice, `@inquirer/prompts`). Service starts **after** hash is written. | S01-T03, S01-T09 |
| P2 | Hash: **Argon2id primary**, auto-fallback **bcrypt** if native build fails at install, **PBKDF2** only via `AGENT_REMOTE_CONTROL_HASH=pbkdf2`. Algorithm recorded in `config.json` (`security.passwordHashAlgorithm`). | S01-T03 |
| P3 | Cookie signing secret in **separate file** `~/.config/agent-remote-control/secret.key` (32 random bytes, mode `0600`), generated by `install`. | S01-T04 |
| P4 | TypeScript: **ESM + `NodeNext` + `target: ES2022` + strict** with `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, `isolatedModules`. | S01-T01 |
| P5 | Persistence envelope: every JSON file is `{ version: number, data: T }`. Helper **refuses** files without `version`. `version: 1` from day one. | S01-T02 |
| P6 | Logger: **Pino via Fastify default**. JSON in prod, `pino-pretty` only when `NODE_ENV=development`. Redact list applied globally. | S01-T01, S01-T05 |
| P7 | Repo layout: **single `package.json`**. Frontend deps as `devDependencies`. Promote to `pnpm` workspace only on real friction. | S01-T01 |

Smoke-import `node-pty` in S01-T01 even though this sprint does not use it —
verifies ESM + native build path works before sprints 05 and 06 depend on it.

## Acceptance Criteria

- AC-001: Ubuntu install creates a running `systemd --user` service.
- AC-002: Web UI reachable at `http://127.0.0.1:4096`.
- AC-003: Login required before any non-login endpoint.
- AC-026: `0.0.0.0` requires explicit config + non-default password.
- AC-027: Busy port fails clearly without killing the existing process.
- AC-036: First-run password setup produces non-plaintext hash; sessions use
  server-issued IDs.

## Deliverables

- `package.json`, `tsconfig.json`, `src/` skeleton (TypeScript + Node.js 20).
- `bin/agent-remote-control` (CLI entry).
- `src/cli/{install,start,stop,status,open,config}.ts`.
- `src/server/core/{app,auth,config,persistence,envelope}.ts`.
- Authenticated route registry + allowlist test for the only public routes:
  `/login` and login static assets.
- systemd unit template: `~/.config/systemd/user/agent-remote-control.service`.
- Default config at `~/.config/agent-remote-control/config.json` matching the
  schema in REQUIEMENT.md "Default Configuration".
- Login page at `/login` (vanilla HTML is fine for this sprint).

## Tasks

- **S01-T01** Scaffold TypeScript project (ESM, `NodeNext`, `ES2022`, strict
  per P4), single root `package.json` (P7), Fastify server with Pino default
  logger (P6), ESLint + Prettier. Smoke-import `node-pty` to validate native
  build under ESM.
- **S01-T02** Implement `config.ts` + persistence helper: schema-versioned
  envelope `{ version, data }` (P5), refuse to load files missing `version`.
  Atomic write via `proper-lockfile` + write-temp-then-rename, file mode
  `0600`, parent dir `0700`.
- **S01-T02B** Implement `envelope.ts`: one command response helper and one
  normalized error factory for every HTTP command route. Success shape is
  `{ok: true, data, error: null}`. Failure shape is `{ok: false, data: null,
  error: {code, operation, message, detail?, recoveryAction?}}`.
- **S01-T03** Password setup flow inside `install` (P1): `@inquirer/prompts`
  confirm-twice, min length 12. Hash with Argon2id; on argon2 native build
  failure auto-fallback to bcrypt; honor `AGENT_REMOTE_CONTROL_HASH=pbkdf2`
  override (P2). Record `security.passwordHashAlgorithm` in `config.json`.
- **S01-T04** Session middleware: random 32-byte session IDs signed with key
  from `~/.config/agent-remote-control/secret.key` (P3 — generated by
  `install`, mode `0600`). HttpOnly + `SameSite=Lax` cookie, `Secure` when
  HTTPS enabled. Idle timeout from config. Sessions persisted via the
  versioned helper from T02.
- **S01-T05** Implement login endpoint: rate-limit (10 fails / 5 min per IP),
  generic error messages, CSRF token issuance.
- **S01-T06** Implement CSRF middleware: double-submit cookie pattern for all
  state-changing endpoints.
- **S01-T06B** Implement route auth allowlist test: build the Fastify route
  table in test mode and fail if any HTTP route except `/login` and login
  static assets is unauthenticated. `/api/auth/logout` is authenticated and
  CSRF-protected.
- **S01-T07** Implement port-busy check: try-bind, fail with normalized error
  envelope on EADDRINUSE. Never call `killPortProcess` (POC does this — do NOT
  port that behavior).
- **S01-T08** `0.0.0.0` config gate: refuse to start if bind host is 0.0.0.0
  and password is empty or default. Print red startup banner with risks.
- **S01-T09** CLI commands:
  - `install` — write systemd unit, `systemctl --user enable --now`.
  - `start` / `stop` — proxy to systemctl.
  - `status` — print bind addr, PID, uptime.
  - `open` — `xdg-open http://<host>:<port>`.
  - `config` — print or edit config path.
- **S01-T10** Minimal `/login` HTML page (no SPA yet) +
  authenticated `/api/auth/logout` POST.
- **S01-T11** Smoke tests:
  - install → service starts → curl returns 401 → login → curl returns 200.
  - Bind 0.0.0.0 with default password → server refuses to start.
  - Port busy → clear error.
  - Unauthenticated route allowlist test fails for any newly exposed route.
  - Login/logout/config failures return normalized error envelopes.

## Risks

- **systemd unit working-dir + PATH:** Need `Environment=PATH=...` so the node
  binary is found under `systemd --user`. Test on a clean Ubuntu install.
- **Argon2 native build on user machines:** Provide bcrypt or PBKDF2 fallback
  (REQ-014A allows both).
- **systemd user service autostart without graphical login:** `systemctl --user
  enable` only auto-starts on session login. For a headless or SSH-only setup
  the user needs `loginctl enable-linger $USER` so the service starts at boot
  and survives logout. The `install` command should detect non-graphical
  installs and either run `enable-linger` (with user consent) or print
  guidance.

## Done Definition

- All AC items above pass manual test.
- `agent-remote-control install` on a fresh user shell produces a running
  service responding 200 on the login page and 401 elsewhere.
- Config file permissions are 0600.
- Config directory permissions are 0700; persisted JSON writes are atomic and
  schema-versioned from day one.
- Every HTTP command route shipped in this sprint returns the normalized
  envelope.
- Route auth allowlist test is in place before later sprints add APIs.
- No `kill` commands ship in the install path.
